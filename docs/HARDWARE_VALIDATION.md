# 真实硬件无桨安全验证

这些步骤是代码与模拟测试通过后的首次硬件验收流程，不代表本次软件修改已经完成真实硬件验证。

## 前置条件

- 拆除桨叶；如无法拆除，推进器必须可靠悬空并清空周围人员和物品。
- 准备示波器或逻辑分析仪观察 PCA9685 输出。
- 电调急停/断电手段在操作人员触手可及的位置。
- Orange Pi 与 STM32 都使用协议 v2 固件；不要混用旧版一端。
- 首轮只允许单通道、短持续时间和 `1500–1510us` 范围。

任何通道上电后不是 `1500us`、页面确认值与示波器不一致、串口出现裸文本、或安全状态不明确时，立即断开推进器电源并停止验证。

## 验证顺序

1. 不连接桨叶，上电但保持 DISARMED。确认 8 路都是 `1500us`，Web 同时显示串口、STM32、状态新鲜度和传感器新鲜度。
2. 不 ARM，直接发送 SET_PWM；预期收到带原请求 sequence 的 `NOT_ARMED` NACK，所有输出保持 `1500us`。
3. ARM 但不进入手动模式，再发送 SET_PWM；预期拒绝且保持 `1500us`。
4. 进入 MANUAL_TEST，确认仍然只有中位输出。
5. CH0 发送 `1510us / 200ms`；其他 7 路必须保持 `1500us`。
6. 确认 200ms 后 CH0 自动回到 `1500us`，状态报告的 `active_channel=0xFF`、`manual_pwm_enabled=false`、回中原因为 `PWM_COMMAND_TIMEOUT`；页面确认值只在收到该状态后更新。
7. 再次执行 `1510us / 2000ms` 并立刻关闭最后一个浏览器页面；预期后端立即回中、退出手动模式并 DISARM，不等待 2 秒持续时间结束。后端与 STM32 心跳应继续用于监控。
8. 再次 ARM/进入手动模式后拔掉 Orange Pi 串口；预期 STM32 在心跳超时内进入 COMM_LOST 并独立回中。重连后必须先回到 DISARMED，不能自动恢复旧输出。
9. 连续拔插串口至少 5 次；确认只有一个 reader、writer 和 reconnect task，旧 pending 请求以 `connection_lost` 失败，服务关闭后没有继续重连。
10. 重启 STM32；确认 Web 很快显示新状态，旧 pending sequence 被清理，缓存状态不会因心跳而被误标为新状态。
11. 注入一帧 CRC 错误或前置随机噪声；确认错误计数增加，紧随其后的合法帧仍能解析。
12. 以上全部通过后，才逐步测试单通道 `1530us`，再视现场安全评估测试 `1550us`。仍使用短持续时间，不进行高速或多通道带桨测试。

## 建议记录

每一步记录固件 commit、Orange Pi commit、串口端口、测得脉宽、ACK/NACK sequence、状态报告时间、回中原因、Web 截图和是否通过。失败项必须保留原始二进制日志与示波器截图，修复并重新从第 1 步开始。
